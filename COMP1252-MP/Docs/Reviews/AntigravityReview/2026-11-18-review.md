## Findings

1. **P1: the ingested scenes cannot enter frozen pixel QA.**
   `adapt_validation_scenes.py:17,63-87` plans seven feature bands and cloud
   GML. Actual scenes contain seven JP2 s and three metadata files each.
   `pixelqa_scene_metadata.py:17-20,119-142` additionally requires
   B01/B05/B09/B10 and all 44 per-band NODATA/SATURA/DEFECT/TECQUA GML files.
   Both actual scenes return `metadata_usable=False` with 48 missing-input
   issues. `assess_pixel_quality.py:284-287` refuses them before pixel reads.
   The weaker seven-band inventory predicate used by V9 is not QA readiness.

2. **P2: existing nonempty files bypass source validation.**
   `ingest_validation_scenes.py:92-97` trusts any nonempty existing file, while
   line 111 calls its downloader without the optional expected byte size.
   A newly computed local SHA records bytes; it does not prove the existing
   file matches the source object. Correction must compare expected source
   size/MD5 as well as the preserved V9 SHA hashes.

3. **P2: failed ingestion can leave discoverable partial scenes.**
   `ingest_validation_scenes.py:80-87` places downloads directly under final
   Sentinel-2 product paths before pair registration/coverage succeeds.
   Guard cleanup removes report staging, not those assets. Correction needs
   complete staging outside discovery, validated prerequisites and recoverable
   publication rather than partial final scenes.

4. **P2: historical compatibility/size summaries overstate their evidence.**
   `audit_validation_catalogue.py:375-378` hardcodes AWS baseline N0206/zero
   offset despite mixed N0500/N0206 archived items; first-item selection at
   lines 348-349 can yield N0500 pair evidence. V8 embeds estimated sizes and
   a constant 32 GiB disk figure, and its skeleton test never asserts all reader
   issues absent. These claims cannot establish source-specific compatibility.
